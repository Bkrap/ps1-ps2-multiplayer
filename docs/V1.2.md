# PS1 Rooms — v1.2

Target: browser/input reliability and playability polish after the v1.1 LAN multiplayer baseline (lobby, Selkies rooms, DualShock live-test bar, HTTPS for Wi‑Fi, encode tuning).

## Goals

- Chrome (and Chromium) must see physical pads as reliably as Firefox on macOS.
- Keep Pad 1 / Pad 2 isolation solid when both clients are live.
- Keep latency acceptable on a single local machine hosting the room.

---

## Must fix

### Chrome gamepad support

**Problem:** On macOS, Firefox exposes the physical pad via the Gamepad API; Chrome often reports `navigator.getGamepads()` length `0` even when the OS shows the pad connected. Lobby Arm pad / DualShock UI and Selkies in-stream input both depend on that API, so Chrome players get no control.

**Likely causes (from v1.1 debug):**

- Chrome Gamepad API vs DualSense / Bluetooth quirks on macOS
- Steam Input (or similar) exclusive-grabbing the device for Chromium
- In-IDE / Electron browsers that implement `getGamepads` but never populate devices
- WebHID can sometimes see the device while Gamepad API does not

**v1.2 work:**

- [ ] Reproduce on Chrome stable / Edge with wired USB and Bluetooth; document which pads fail
- [ ] Detect empty Gamepad API + available WebHID and show a clear Chrome-specific recovery path (quit Steam, use USB, or use Firefox)
- [ ] Prefer a Chrome path that works without asking users to switch browsers when possible:
  - [ ] Evaluate WebHID → synthetic Gamepad / remapping layer for the lobby tester
  - [ ] Evaluate whether Selkies can consume remapped input, or whether Chrome must be fixed at the Gamepad API layer only
- [ ] Add a short “Supported browsers” note in the lobby (Firefox OK; Chrome needs USB / no Steam until fixed)
- [ ] Automated or manual checklist: Arm pad → Ready → Focus stream → fighter moves, in Firefox **and** Chrome

**Acceptance:** Pad 1 and Pad 2 can each Arm → Ready → control their fighter in Chrome on the same Mac setup that works today in Firefox, without requiring Firefox.

## Out of scope for v1.2

- Touch / on-screen virtual pads
- Per-button remapping UI
- Multi-room production scaling / GPU encode

## Notes from v1.1

- Lobby DualShock bar uses the native Gamepad API (Arm pad unlock).
- LAN clients must use **https://&lt;host-ip&gt;:8791** (Selkies requires a secure context; plain HTTP on a LAN IP fails).
- Firefox is the known-good browser for gamepads on the current Mac + pad setup until this Chrome work lands.
